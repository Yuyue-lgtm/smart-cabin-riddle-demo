# 实时主持上下文与座舱状态

## 每轮聊天上下文

前端为聊天请求构造紧凑状态包，而不是发送全量游戏历史：

- 当前谜题、进度、已覆盖事实与最近已问问题；
- 当前说话者、座位、人设和乘客关系；
- 最近 6 条对话；
- 当前车速、目的地、外部环境和语义感知快照；
- 当前事件及前端计算的优先级；
- 闲聊与拉回游戏的轻量标记。

不发送隐藏提示 `game.hint`、完整乘客矩阵、全量时间轴或整局历史。真实用户输入仍由 Chatflow 同一 `conversation_id` 的近 10 轮记忆承接；开始新局不重置 conversation ID。

## 静默状态同步

`cabin_snapshot` 是 Dify Chatflow 的字符串型会话变量，保存最新车速、环境、目的地、驾驶员/乘客状态和游戏状态。前端在车速、场景、乘客/驾驶员状态和局面发生变化时，经同源 `/api/workflow` 静默更新会话变量，不调用模型。状态调用会防抖并串行写入；重要事件发送前先 flush，避免模型读到过期快照。

第一次 Chatflow 请求返回 `conversation_id` 后，前端马上写入初始快照。若还没有会话 ID，状态先保留在本地，后续首次请求会携带当前状态并补写会话变量。

## 主动事件和话术时序

- `environment_change` 在座舱背景刚变化时立刻调用 Chatflow；不等中控屏 2 秒延迟切换。
- Chatflow 环境话术不由前端暂存到中控屏切换时才显示。返回后作为 P1 话术进入现有仲裁；正在播报时等待当前话术结束，新环境 P1 替换尚未显示的旧环境 P1。
- 中控屏背景仍按现有 2 秒延迟独立切换。
- 车速普通变化仅静默同步。车速从未超限状态进入 `>120 km/h` 时触发一次 `speed_overspeed` P1；处于超速期间的后续数值变化只同步状态。
- 急刹沿用前端 P0 立即暂停和后端确定性安全回复。主驾疲惫/睡着持续超过 15 秒后才主动调用主持人，沿用现有疲惫事件等级。
- 驾驶状态恢复为正常后取消未触发的 15 秒计时并同步快照。

事件队列、优先级仲裁、气泡最多 6 秒、Sprite 动画、倒计时、座舱 UI 和实际动作执行都归前端。Chatflow 只返回自然语言、结构化决策和动作计划。

## 感知 / 决策 / 执行

Chatflow 结构化输出：

- `perception.source`、`fusion_conclusion`、`confidence`；
- `decision_trace.layer`、`matched_rule`、`priority`、`decision`、`policy`、`guard_status`、`hint_blocked`；
- `execution.actions`、`timing`、`fallback`。

答对的 P0 规则输出 `ambient_light.play_preset: cabin-correct-light` 作为可视计划；前端现有答对逻辑仍负责真正触发灯效。自然语言音乐请求经过模型回复后，输出守卫从明确的开/关表达确定 `music.set_enabled` 方向，再由前端执行并记录结果。模型返回相反布尔值时以显式指令为准；“不要关闭音乐”保持原状态。车内照明灯、空调不开放。提示请求始终由确定性输出守卫拦截。

## 前端状态初始化

`DEFAULT_STATE` 必须保持可被 `structuredClone` 复制。静默同步队列默认值为 `null`，复制成运行状态后才赋值 `Promise.resolve()`。不能将 Promise、DOM 节点等运行时对象直接放入默认状态，否则脚本会在 `boot()` 前中断，导致整体缩放、准备页样式和事件绑定一并失效。

优先级由前端单点计算，Chatflow 不从话术或自由文本重新推导：

| 事件 | 优先级 / 规则 |
| --- | --- |
| 急刹 | P0，立即前端兜底暂停 |
| 答对、超时揭晓、整局结束 | P0，Chatflow 确定性分支 |
| 环境变化、首次超速进入 `>120` | P1 |
| 主驾疲惫/睡着超过 15 秒 | 使用现有疲惫事件等级 |
| 聊天和普通乘客互动 | 由前端按已有映射传入 |

## 时延与验证

静默同步不触发模型；只有聊天和重要事件走 Chatflow。高频速度变化通过状态同步防抖，超速话术仅边沿触发。Dify 发布草稿后验证：

1. 修改环境时 Network 显示一个静默 `sync_state` 请求和一个环境事件 Chatflow 请求；环境话术不等 2 秒后的中控屏背景更新。
2. 连续切换环境时，旧的待显示环境 P1 被最新事件覆盖。
3. 车速 `110 -> 121 -> 125` 只发一次超速事件；降至 `120` 再升至 `121` 后可再次触发。
4. 主驾疲惫不到 15 秒恢复时没有主动话术；持续超过 15 秒时触发一次。
5. 三个面板能显示 Chatflow 返回的感知、规则/模型决策、动作计划和前端实际执行结果。
6. 答对灯效来自前端答对路径；音乐可通过自然语言开关并显示执行结果；照明灯/空调不执行。
