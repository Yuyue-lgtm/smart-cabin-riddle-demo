# 实时主持上下文与座舱状态

2026-10-18多事件调度以 [主持人多事件队列](HOST_EVENT_QUEUE.md) 为准：P0抢占，其余话术等当前气泡结束，按优先级/同级FIFO依次显示。事件依赖按目标独立检查，不因无关乘员或环境变化丢掉；生成前需刷新分析时重取签名。当前题普通问答保留局/题/谜底/P0校验，无关座舱变化不抹掉回答。

2026-10-18新增 [座舱情境协同](CABIN_SCENARIO_POLICY.md)：`game.public_clues` 来自实际已展示内容，`car.zone_lights` 和 `car.sleep_comfort_seats` 描述当前分区模拟。临时打断保留问题、已公开事实和计时，4.5秒后接续；普通车控/求助不扣问题次数。不同来源/浏览器会话隔离、同源全局会话复用保持不变。

## 每轮聊天上下文

前端为聊天请求构造紧凑状态包，而不是发送全量游戏历史：

- 当前谜题、进度、已覆盖事实与最近已问问题；
- 当前说话者、座位、人设和乘客关系；
- 本题最近 6 条对话保留在前端请求快照中，供兼容处理；Chatflow 输入节点在构建模型上下文时移除这份 `recent_messages`，避免与最近 10 轮 Dify Memory 重复注入；
- 当前车速、目的地、外部环境和语义感知快照；
- 当前事件及前端计算的优先级；
- 闲聊与拉回游戏的轻量标记。

不发送隐藏提示 `game.hint`、完整乘客矩阵、全量时间轴或整局历史。同一浏览器同源的 `conversation_id` 和稳定 `user_id` 跨题、跨新局、刷新持续复用。已问问题、覆盖事实、进度和前端近期对话仍按当前 `round_id` 筛选；跨题的自然对话连续性由 Dify Memory 保留。

每轮聊天携带 `round_context`：当前和上次成功聊天的局/题标识、`transition` 和当前快照优先标记。新题首次聊天携带“上一题已结束，当前题快照优先”；成功且仍属于当前题的响应才确认新范围，请求失败会在下次重发边界。BFF 重建固定说明，Chatflow 将其放入本轮系统上下文；玩家原话保持原样，不增加虚构玩家消息或单独的换题模型调用。

历史可用于称呼、语气、闲聊和明确的旧题回顾。当前问题没有明确指向旧题时，“它”“答案”指当前题；当前 `game.current_answer`、事实目录和 `game.status` 优先，旧题已揭晓不能让新题被当成结束。该方式保留模型记忆，因此仍需回归跨题语义，范围校验本身不能证明自然语言回答正确。

## 快照与路由

2026-10-17新增 [情境串行路由](SITUATION_DIALOGUE_ROUTING.md)：事件先分析，再由前端自动调用Chatflow。两步共用事件ID，第二步为 `route=chat, operation=situation_reply`，携带服务端签名交接凭据并使用全局会话队列。情境串词不触发思考动画，不应用游戏状态或动作。`scene_version` 也覆盖僵局/接近答案等进度变化。

`/api/workflow` 按 `route=chat` 与 `route=situation` 分别调用对话 Chatflow 和情境 Workflow。每次请求携带当前快照、稳定 `user_id`；聊天请求携带全局持久化的 `conversation_id`。前端不再调用 `sync_state` 或写入 `cabin_snapshot` 会话变量。

`game_id` 每局变化，`round_id` 每题变化；`scene_version` 由环境、目的地、超速区间、驾驶员/乘客状态、游戏状态和 P0 中断代数计算，不因普通提问次数或未跨阈值的车速变化而变化。事件有独立 `event.id`。BFF 返回实际路由和事件标识；前端校验作用域、有效期和请求顺序后才采用结果。

聊天 BFF 返回 `game_id/round_id/scene_version`；Chatflow 结构化 `host_result.context_scope` 回显其实际解析的快照范围。收到不匹配范围时 BFF 返回 `DIFY_CHAT_CONTEXT_MISMATCH`，前端也在存会话 ID、显示话术前检查范围。发布 API 没有暴露结构化节点输出时，保留自然语言兼容模式并标记 `context_verified=false`；此时不能宣称已经验证模型读取的范围。

## 提问预演和思考状态

进入准备页即预取首题，进入第 N 题即预取第 N+1 题，结算页预取下一局首题。预演时确定目标题及自动事件模板，返回后存入按局/题标识隔离的运行时缓存；当前题与下一题可以并行请求。结算页已发起的下一局首题在继续挑战时直接复用。准备页更换体验线或环境导致首题变化时取消旧预演并重取。

预演快照中的谜底、主题、题号均属于目标题，已问问题、覆盖事实和近期对话清空。预演结果不写聊天记忆、不修改玩家的全局会话 ID，也不修改主持人气泡或游戏状态。预演的 `scene_version` 用于本次请求与响应关联；缓存使用时校验的是局、题、谜题、乘客关系及事件模板，不因普通环境变化或 P0 自动丢弃纯问题计划。

`isHostBusy()` 只表示实时 Chatflow 问答在途。预演不阻塞开题和倒计时；没有有效预演时，模拟乘客不提问，不使用本地问题。晚到计划保留当前题已问和已覆盖的记录，只在后续自动提问时使用尚未问过的步骤。急刹、答对和超时保留预演缓存，暂停时不安装；恢复后的聊天或自动提问会采用匹配的已完成计划。

本地支持预演 `partial` 安全前缀先用，并在后台修复后续一次。修复请求仍归属原目标题，不占用问答锁或思考状态；完成后只扩展计划，不清空已问步骤和覆盖事实。P0 保留这类纯问题修复；换局、重置及替换首题取消旧修复，迟到返回不能回填。云端节点的最新草稿及发布状态需通过 Dify Console 重新读取；历史连接器 401 不能作为当前状态依据。

乘客发言气泡对主持人回复的最短展示窗口为 1500ms；接口返回较快时只等待剩余时间，网络等待已超过窗口时不再额外延迟。

思考动画只由实际 Chatflow 问答请求的 300ms 等待计时器触发；开始后单次播完。情境分析、预演、本地开场不触发思考。刷新页面准备第 1 题新局，同源 Dify 全局会话与用户 ID 继续复用。

实际等待回复与请求收尾分别记录：接口成功/失败后立即结束等待，清除未触发的思考计时器；尚未加载完成的思考切片也取消，不能在回答后迟到播放。已经开始播放的当前思考序列则保留到自然结束，新的回复气泡可以同时显示，不能因气泡的 1500ms 保护而中断并重播。播放完成后清除思考标记；无新 Chatflow 等待时，残留标记也不能触发思考。旧请求的计时器回调不能清除新请求的计时器引用。

所有主持人话术气泡从首次渲染起至少显示 1500ms，思考状态或后续话术都不能提前隐藏/替换；保护期内到达的新话术按原有优先级保留并延后显示。乘客气泡对主持人回复也至少展示 1500ms。保护期结束后，思考动画仍按原有 300ms 延迟启动。

## 主动事件和话术时序

- `environment_change` 在座舱背景刚变化时调用情境 Workflow；不等中控屏 2 秒延迟切换。
- 环境变化校验前后环境、event.value与当前状态后，情境Workflow走P1规则快速分析；前端收到有效发言建议自动接续Chatflow生成串词。网络失败或静默结果不补本地环境短句；第二步直接携带本次签名分析，不等待下一次乘客发言。
- 其他非P0情境结果仍需明确 `request_proactive_speech=true` 且匹配当前作用域、未过期，候选话术才进入前端优先级仲裁。
- 环境话术可在普通气泡至少展示1500ms后优先显示，原乘客回答和期间返回的新回答进入有序待播队列，环境话术结束后继续显示。队列校验局、题、P0代数及30秒有效期，P0或重置清空；P0/P1已有话术仍优先完成。不同类型的情境请求互不覆盖，同类请求只接收最新一条；连续环境变化不播旧环境。
- 静默结果只更新分析面板并记录“本次未申请发言”，不会留在“正在核对”。“经验库检索：本次无需检索”仅说明RAG状态。
- 中控屏背景仍按现有 2 秒延迟独立切换。
- 普通车速变化只更新前端状态，下一次请求携带最新值。车速从 `<=120` 进入 `>120 km/h` 时触发一次 `speed_overspeed` P1。
- 急刹由前端 P0 立即暂停、显示本地安全话术，并异步通知情境 Workflow；通知结果只存分析记录，不修改本轮气泡、动画或游戏状态。主驾疲惫持续超过 15 秒后才调用情境 Workflow。
- P0安全/揭晓话术直接抢占，不受普通气泡1500ms最短显示保护延迟；急刹仍由本地4500ms计时恢复。后台分析不决定恢复时机。
- 答对揭晓期间，玩家仍可向主持人发起聊天；同题、同一P0代数的 Chatflow 回复只进入话术队列，不得改变胜利状态、答案 UI 或揭晓动画。揭晓时环境版本变化不使同题回复失效。明确的“夸我/表扬我”请求使用短赞美回应，避免 Chatflow 将其重复解释成答对揭晓。P0播报结束后显示回复，并在回复气泡结束前暂停自动换题；切题后迟到的旧题回复仍按局、题和P0代数丢弃。揭晓期间不播放思考动画；失败/空结果静默，不落通用兜底。
- 驾驶状态恢复为正常后取消未触发的 15 秒计时。

事件队列、优先级仲裁、气泡最多 6 秒、Sprite 动画、倒计时、座舱 UI 和实际动作执行都归前端。Chatflow 只返回自然语言、结构化决策和动作计划。

2026-10-17新增 [主持经验v2](HOST_EXPERIENCES_V2.md)：27条云端经验与首批8类反馈/偏好接入。真实本局成绩通过`performance`提供，偏好通过`host_preferences`保存；`post_result_feedback`是P0完成后的P4窗口，最多一句，模型未及时返回时只用对应真实成就短句。明确夸奖请求由Chatflow回应，不再用固定赞美覆盖有效模型话术；揭晓状态中的普通聊天不再自动重复进入P0。

## 感知 / 决策 / 执行

Chatflow 结构化输出：

- `perception.schema_version: 2`、`source`、`signals`；`confidence: null`，不伪造置信度；
- `decision_trace.layer`、`matched_rule`、`priority`、`decision`、`policy`、`guard_status`、`hint_blocked`；
- `execution.actions`、`timing`、`fallback`。

面板逐项换行显示输入事实、具体处理选择、实际执行回执。来源、优先级、规则标识、模型层级、守卫结果等技术信息留在原始记录中，不作为比赛主展示内容。无动作不填充通用动作/时序说明。决策只依据实际命中的代码分支或已接受的模型回复方式，不声称展示模型推理过程。

执行栏由前端真实回执驱动，不直接展示 Chatflow 计划为成功：气泡可为等待/显示中/显示结束/被替换/取消；音乐必须等 `play()` 成功并确认未暂停，失败展示浏览器拦截或播放失败；答对灯仍由本地正确答案路径触发，写明“模拟”。每条记录有独立 ID，旧回执不覆盖新事件。历史附带 `execution_receipts`。旧版输出不足以解释决策时明确标记缺少记录；本地流程与预生成问答不冒充实时 AI 决策。

答对的 P0 规则输出 `ambient_light.play_preset: cabin-correct-light` 作为可视计划；前端现有答对逻辑仍负责真正触发灯效。自然语言音乐请求经过模型回复后，输出守卫从明确的开/关表达确定 `music.set_enabled` 方向，再由前端执行并记录结果。模型返回相反布尔值时以显式指令为准；“不要关闭音乐”保持原状态。车内照明灯、空调不开放。提示请求始终由确定性输出守卫拦截。

## 前端状态初始化

`DEFAULT_STATE` 必须保持可被 `structuredClone` 复制。提问预演的 Promise、AbortController 等存放在独立运行时 Map。不能将 Promise、DOM 节点等运行时对象直接放入默认状态，否则脚本会在 `boot()` 前中断，导致整体缩放、准备页样式和事件绑定一并失效。

优先级由前端单点计算，Chatflow 不从话术或自由文本重新推导：

| 事件 | 优先级 / 规则 |
| --- | --- |
| 急刹 | P0，立即前端兜底暂停 |
| 答对、超时揭晓、整局结束 | P0，前端确定性处理，异步通知情境 Workflow |
| 环境变化、首次超速进入 `>120` | P1 |
| 主驾疲惫/睡着超过 15 秒 | 使用现有疲惫事件等级 |
| 聊天和普通乘客互动 | 由前端按已有映射传入 |
| 真实副驾持续未参与 | P4，情境 Workflow 判断是否邀请，前端检查当前对话空闲和活动版本 |

副驾邀请不再由固定时间轴串词触发。前端只记录本题参与状态：副驾未发言20秒、所有对话空闲2.5秒且剩余答题时间大于15秒时，每题发送一次 `passenger_inactive` 分析机会。正在问答、有排队输入、暂停、睡眠或用户明确要求自己想时保持安静。Workflow可选择不说话；候选邀请10秒失效，不缓存为后续聊天策略。新提问或主持人新发言会递增独立的参与活动版本，使返回较晚的旧邀请失效，不改变普通聊天的 `scene_version` 规则。

## 时延与验证

普通状态变化只保留在前端快照；下一次聊天或重要事件携带最新状态。超速话术仅边沿触发。Dify 发布草稿后验证：

1. 修改环境时 Network 显示一个 `route=situation` 请求，没有 `sync_state` 请求；环境话术不等 2 秒后的中控屏背景更新。
2. 连续切换环境时，旧的待显示环境 P1 被最新事件覆盖。
3. 车速 `110 -> 121 -> 125` 只发一次超速事件；降至 `120` 再升至 `121` 后可再次触发。
4. 主驾疲惫不到 15 秒恢复时没有主动话术；持续超过 15 秒时触发一次。
5. 三个面板分别显示输入事实、Chatflow 具体处理选择和前端真实执行回执；原始动作计划仅保留在记录中，不当作已执行。
6. 答对灯效来自前端答对路径；音乐可通过自然语言开关并显示执行结果；照明灯/空调不执行。
