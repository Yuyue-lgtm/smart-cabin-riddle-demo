# 游戏加载页

2026-10-21，本地实现 Figma `377:46`「Pencil 1:1 / 游戏加载」。仅替换中控屏的1440×810画布，加载期间禁用座舱选择与手动控制区。图标使用 `assets/game-icon-loading.png`（130×130），并复用于游戏进行中、揭晓页及网页标签；加载页显示130×130、圆角30，内容块坐标(441,301)、宽558，进度轨558×12。

## 进入准备页的条件

准备页图片、招呼动画、字体，以及默认场景「高速亲子出行」的首题预演均完成后，实际进度到100%，自动进入准备页。图片等待解码；进度按任务完成及固定权重计算，不按时间伪造百分比。其余五个场景不参与进入条件。准备页的人偶与新手引导均在进入准备页后启动，引导仍等待4秒并沿用本地关闭记录。

首题预演只在完整 `ready` 时计为成功；安全前缀 `partial` 仍保留，但显示为未完全就绪。发生失败或等待20秒后显示「重试失败项 / 先进入」。重试只重新运行失败项，已成功的图片和预演保留；尚在进行的预演不重复发起，此时重试按钮禁用，仍可先进入。先进入后，原有进行中的请求继续完成，部分预演仍可按原规则使用。

## 后台预加载

进入准备页后，依次准备另外五个场景的首题预演，最多同时新增一条后台预演请求；同时分批加载主持人其他动效、场景背景与乘客默认图片。页面失焦、隐藏或模拟暂停时不启动新的后台任务，已发出的网络请求按原超时机制结束。Dify健康与连通性检查沿用现有逻辑，不产生模型调用；不预生成主持人回复或语音。

六个场景先各准备一份首题预演，键包含场景、默认乘客关系、首题和轮次剧本。首次进入该场景使用已预留的剧本；后续新局仍随机选择首轮剧本，只有匹配的缓存才复用，未命中则准备新的模板。每次新游戏仍使用独立game ID，复制计划时改为当前round ID。切场景、重置和普通预演清理不会取消模板请求；切换场景时也不会把其他场景的结果写入当前题目。缓存仅在页面内存中保留，刷新后重新生成，以避免沿用Dify更新前的结果。

## Safari 黑屏排查与布局保护

2026-10-21：原生 Safari 普通刷新未复现用户的偶发黑屏。故障注入确认两个布局缺口：零高度会把整页缩放为0，暂停时的resize又不会恢复整页布局。现在无效尺寸保留上一次可用布局，resize、pageshow和focus均重算页面几何，即使游戏暂停也生效；这些操作不会自动恢复游戏或抢焦点。

同时修复了诊断链路：前端已发送的`client_error`曾被HTTP入口拒收，现在与`page_state`均能写入日志。页面状态只含启动/准备完成阶段、视口与根节点尺寸及可见性，不包含题目、用户输入或密钥。原生Safari已验证4次加载/刷新、零尺寸保护、暂停时布局恢复，并验证模拟脚本异常确实落盘；截图和状态证据保存在`tmp/safari-black-screen/`。这些结果证明已修复布局缺口，尚不能证明用户先前那次黑屏必然由该缺口触发。
