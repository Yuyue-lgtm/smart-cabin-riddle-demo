# 旅途主持人：五条黄金体验线（可编辑脚本）

编排日期：2026-10-22。状态：已应用于本地 Demo 预览；未发布到线上或修改 Dify 工作流。

本稿只使用本次提供的环境和事件，包含补充的“雨天（白天下大雨）”。旧版体验线中的高速、海边等未列出的环境不带入本稿。

## 演示目标与现有 Demo 衔接

黄金体验线用于稳定展示一段完整体验：

```text
座舱感知 → 融合决策 → AI 主持控场 → 网页执行反馈
```

- 黄金线切换的是整套场景配置，不是单独切换环境；它设置初始环境、车速、目的地、乘客关系和首题。手动控制区仍可单独调整环境或触发事件，作为自动时间轴的排练备用；手动覆盖后应按实际状态验收，不能记成自动脚本已触发。
- 每题仍会随机选取一条现有单题问答时间轴，并避免连续两题重复同一模板；本稿的场景事件使用独立全程时钟，跨换题持续运行。自动提问和场景事件共享至少 5 秒的触发间隔。
- 模拟乘客问题来自该题的 Dify 预演计划，发言座位在运行时按驾驶安全、睡眠状态和可参与性选择，副驾始终留给真实用户。没有有效预演或没有合格问题/座位时跳过模拟发言，不用本地问题池或本稿参考句补播。
- 真实用户输入固定属于副驾；主持人请求繁忙时沿用现有输入队列，不由脚本自动代答。
- 高优先级安全事件由前端立即执行，不等待 Dify；环境变化保持当前题和已确认事实不变，只影响后续应景选题。右侧座舱背景先更新，中控屏沿用现有约 2 秒延迟同步。
- 融合决策面板用于展示实际输入事实、处理选择与前端执行回执。Dify 的动作计划不等于动作已成功；音乐、气泡、灯效等以页面真实回执为准，答对灯效明确属于模拟。

## 二、修改方式与时间口径

- 每条线按约 5 分钟编排，不绑定题号或题段。第几题、何时换题由玩家答题、超时及现有游戏流程决定；单题仍是 90 秒，每局仍为六题。黄金线不能指定某时刻必定进入某一题。
- 表格采用 `分:秒` 的全程时间，从游戏开始计时，换题、揭晓或游戏安全暂停不将场景时钟归零；场景状态仍可继续变化。只有“暂停模拟”才冻结整个模拟时钟，恢复后继续剩余时间。
- 每条线的计划窗口为 `00:00–05:00`，最后一项安排在 `04:40`，余下约 20 秒用于收束和留白，不新增强制结束事件。五分钟结束后不重播场景事件，游戏可继续；若整局提前结束，则取消尚未触发的场景事件。重置或切换黄金线后重新计时。
- 每个表内事项都与上一项至少间隔 5 秒；取消原来的相同时刻组合触发。环境、睡眠、驾驶状态仍可先后发生并持续叠加。
- 单题模拟提问在题内 `00:10 / 00:30 / 00:50 / 01:10` 中按模板选取，与场景时钟独立。两类自动调度碰到同一时刻时顺延，确保实际触发相隔至少 5 秒。参考句仅用于编辑，不保证每个参考时刻都一定有人发言。
- 自动调度延后时，下一项也至少与上一项实际触发时刻相隔 5 秒，不把到期条目紧挨着补发。安全／游戏暂停期间模拟提问等待恢复，答题倒计时保持冻结；场景事件不等待主持人或网络回复。真实用户输入、手动或真实突发安全事件不受预设间隔限制。
- 要演示“回答被打断”，需以实际 Dify 问答是否仍在处理中为准。拉开事件间隔后不保证每次都会遇到待答窗口，不能仅凭时间轴宣称已完成打断测试。
- `环境切换`、`座舱事件`、`乘客发言参考`、`检查点`是脚本行的分类，不是新增的 Workflow 事件。只有“座舱事件”列出的八类事件可作为本稿新增调度项。
- 检查点只记录现有游戏流程，不新增“道路恢复”“自动猜中”“强制换题”等事件；检查时如果尚未实际恢复或换题，仍以真实状态为准。
- 当前题提前结束时，只取消该题尚未触发的模拟问题，不补播错过的问题；全程场景事件继续，不随题目结束而丢失或重排。
- 表内原发言内容暂时保留，仅供策划参考，不直接渲染成前端乘客气泡、主持人气泡或固定提示，不直接冒充已发生的对话。
- 前端话术只展示 Dify 实际返回且通过现有校验的内容。模拟乘客问题采用 Dify 预演或相应返回内容；主持人实际回答采用实时 Chatflow 返回。没有有效返回时不拿脚本原话补播。
- 参考内容可供后续 Dify 生成设计使用；没有实际返回或真实用户输入时，不将参考句写入对话历史，也不默认相关需求已经发生、设备已经执行。
- 原参考句中的“副驾”等座位词仅保留作原始语义参考，不绑定模拟说话人。Dify 的实际发言须符合当前模拟成员及发言座位，“我这边”也必须指向实际说话者所在分区。
- 副驾真实用户可以自由输入，但黄金线不预设其一定会输入表内句子，也不模拟替其发言。
- 时间表只保留事项，不再设置“预期行为与验收”列；具体话术和动作以 Dify 有效输出为准，仍受既有权限、安全及状态校验。
- “有人睡着”“乘客醒来”只填写事件名称，不写固定目标、联动组或设备操作。实际乘员由实时感知／事件状态提供，Dify 依据该事实处理关怀或恢复；不让模型凭空认定谁睡着。

### 所有体验线共用的行为边界

| 场景 | 预期行为 |

| 模糊灯光请求 | “把灯关了”先确认分区；“副驾这边”“我这边”且发言座位明确后再执行。 |
| 其他请求 | 换主题、查询精确到达时间、调温、普通分区音量控制等均不伪称已执行；自然说明当前不能完成。 |
| 请求提示或抱怨困难 | 由 Dify 判断请求并生成回应，仅可重述本题已经实际展示的公开线索；不从谜底推导新线索、不说出预演中尚未公开的回答。黄金线和前端不拼接固定提示，前端展示 Dify 有效返回。 |
| 主驾疲惫 | 仅安全提醒和停止游戏邀请；不能通过出题、音乐或玩梗给主驾“提神”。测试时可使用已满足现有持续时长门槛的疲惫事件。 |
| 外部环境变化 | 当前题及已确认事实不变；下一题优先从现有题库选取应景候选。无候选时正常选题，不编造“已经准备好”的特定谜题。 |
| 复杂路段后的恢复 | 退出条件不在本次事件列表内，不新增退出事件。只有现有暂停流程实际解除后才检查接续，不用固定等待秒数宣称道路已经安全。 |
| 多状态叠加 | 预设事项至少间隔 5 秒；此前的环境、睡眠、驾驶状态持续进入最新快照。真实安全事件仍先处理，恢复后继续采用有效状态。 |

睡眠空调规则沿用当前实现：入睡时调至用户记忆值，醒来后恢复睡前设置。睡眠事件的自动关怀与玩家直接要求调空调是不同权限入口，后者仍不可执行。

“下一轮应景”在本稿中统一指下一题，不是强制结束整局。环境可在本题中变化，谜底只在自然换题时更新。环境切换沿用当前双屏延迟显示，不以两块屏幕各生成一次环境事件。

## 十、修改与排练检查

| 想调整什么 | 修改方法 | 需要保持的关系 |
| --- | --- | --- |
| 调整节奏 | 修改全程时间及对应 `GOLDEN_TIMELINES.steps[].delay`（毫秒） | 相邻事项至少 5 秒；保持约 5 分钟目标，不绑定题号、不受单题 90 秒限制。 |
| 移动多个事项 | 分别调整每一行，保持先后次序 | 不重新设置相同时间；与模拟提问槽位也至少错开 5 秒。 |
| 调整睡眠／醒来 | 只修改事件时间 | 事件只写名称；成员状态与具体操作由实时数据及 Dify 处理。 |
| 更换环境 | 从九种环境中替换 | 按首个非车库／隧道环境重新计算准备页预览，检查后续选题；不要提前改当前谜底。 |
| 更换打断事件 | 只在支持事件中选择 | 超速或欢笑不能无条件替代真正的暂停恢复测试。 |
| 修改发言参考 | 修改“保留发言参考”列 | 仍不直接用于前端显示或充当实际对话；前端话术来源为 Dify 返回。 |
| 缩短演示 | 先删除可选欢笑或重复车控条目 | 不删除睡醒配对、有效公开线索来源和对应恢复检查。 |

排练时记录真实表现：问题是否保存、次数是否重复变化、设备动作是否实际模拟成功、是否仍邀请睡眠乘员、是否生成多余提示。另检查有没有把参考句直接渲染、有没有副驾自动发言、婴儿是否被安排了完整提问，以及延迟后是否仍留出至少 5 秒的自动触发间隔。脚本参考不能直接当作已发生的对话或已完成的动作。

仍需按现有策略处理复杂路段暂停解除及醒来恢复不覆盖新设置。本轮同步调整本地前端的独立全程事件配置、模拟提问槽位和调度间隔；不新增环境或事件，不修改 BFF 或 Dify 工作流。
