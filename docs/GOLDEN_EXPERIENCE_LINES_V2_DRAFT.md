本稿只使用本次提供的环境和事件，包含补充的“雨天（白天下大雨）”。旧版体验线中的高速、海边等未列出的环境不带入本稿。

## 一、修改方式与时间口径

- 每条线包含连续两题，用 `R1`、`R2` 表示，展示长度约为两题的实际游戏时间加暂停及转场。不是重新启动两局游戏。
- 时间格式为 `分:秒`；每题提示正文出现、开始答题时计为 `00:00`。每题仍为现有的 90 秒，不通过脚本延长。
- 安全暂停时，本题脚本时间与答题倒计时一起冻结；题目介绍、揭晓和换题不计入本题脚本时间。实际演示墙钟时间会更长。
- 同一时间的联动组按表内行序触发，属于一次组合测试。标记为“待答窗口”的条目，必须在玩家问题已经提交、主持人回答尚未显示时触发；如窗口未出现，可人工触发同组安全事件，不假装已经打断了回答。
- 普通发言时间是建议触发点。主持人忙时顺延到当前话术结束，建议留出约 2 秒空隙；安全事件立即执行，其他事件按现有队列和有效性校验处理。
- `环境切换`、`座舱事件`、`玩家发言`、`检查点`是脚本行的分类，不是新增的 Workflow 事件。只有“座舱事件”列出的八类事件可作为本稿新增调度项。
- “恢复后”“下一题开始”是现有游戏流程的检查点，不新增“道路恢复”“自动猜中”“强制换题”等事件。
- 当前题提前结束时，跳过该题尚未发生的脚本项，不补播错过的问题。准备完整演示时，玩家先提属性问题，不提前报谜底。
- 玩家发言示例用于真实副驾输入或人工演示，不把副驾变成自动模拟乘客。自动模拟乘客仍使用预演生成的安全提问，实际主持回答仍走实时 Chatflow。
- 所有台词只约束语义和动作边界，不锁死主持人的逐字表达。

### 所有体验线共用的行为边界

| 场景 | 预期行为 |
| --- | --- |
| 乘员入睡 | 关闭目标分区灯光、分区娱乐音量调至 0、分区空调调至用户记忆值；停止邀请该乘员。只影响该分区，保留其他清醒乘客的参与机会。 |
| 乘员醒来 | 恢复同一分区的睡前设置，轻柔欢迎；灯原来关闭就保持关闭，不强制全部打开。 |
| 普通车控请求 | 仅背景音乐开关、目标明确的分区灯光开关可执行。控制、澄清、帮助均不扣游戏提问次数。 |
| 模糊灯光请求 | “把灯关了”先确认分区；“副驾这边”“我这边”且发言座位明确后再执行。 |
| 其他请求 | 换主题、查询精确到达时间、调温、普通分区音量控制等均不伪称已执行；自然说明当前不能完成。 |
| 请求提示或抱怨困难 | 只重述本题已经实际展示的公开线索，不从谜底推导新线索、不说出预演中尚未公开的回答。 |
| 主驾疲惫 | 仅安全提醒和停止游戏邀请；不能通过出题、音乐或玩梗给主驾“提神”。测试时可使用已满足现有持续时长门槛的疲惫事件。 |
| 外部环境变化 | 当前题及已确认事实不变；下一题优先从现有题库选取应景候选。无候选时正常选题，不编造“已经准备好”的特定谜题。 |
| 复杂路段后的恢复 | 退出条件不在本次事件列表内，不新增退出事件。只有现有暂停流程实际解除后才检查接续，不用固定等待秒数宣称道路已经安全。 |
| 多事件重叠 | 安全处置先执行；环境和乘员状态保留为最新快照；恢复后再处理仍有效的关怀与回复，不丢失原问题、不重复计次。 |

睡眠空调规则沿用当前实现：入睡时调至用户记忆值，醒来后恢复睡前设置。睡眠事件的自动关怀与玩家直接要求调空调是不同权限入口，后者仍不可执行。

“下一轮应景”在本稿中统一指下一题，不是强制结束整局。环境可在本题中变化，谜底只在自然换题时更新。环境切换沿用当前双屏延迟显示，不以两块屏幕各生成一次环境事件。

## 九、修改与排练检查

| 想调整什么 | 修改方法 | 需要保持的关系 |
| --- | --- | --- |
| 调整节奏 | 直接修改该行时间 | 普通发言留有响应空间；所有固定时间小于 01:30。 |
| 移动多事件高潮 | 同时移动对应联动组的所有行 | 保留待答窗口条件和安全优先顺序。 |
| 更换入睡乘员 | 同时修改入睡、醒来、恢复检查和相关描述 | 同一座位闭环；不安排主驾进入乘客睡眠关怀。 |
| 更换环境 | 从九种环境中替换 | 检查后续选题描述与最新环境一致；不要提前改当前谜底。 |
| 更换打断事件 | 只在支持事件中选择 | 超速或欢笑不能无条件替代真正的暂停恢复测试。 |
| 修改玩家台词 | 直接改“玩家原话” | 可执行需求仍只限音乐、明确分区灯光；求助只复述公开线索。 |
| 缩短演示 | 先删除可选欢笑或重复车控条目 | 不删除睡醒配对、有效公开线索来源和对应恢复检查。 |

排练时记录真实表现：问题是否保存、次数是否重复变化、设备动作是否实际模拟成功、是否仍邀请睡眠乘员、是否生成多余提示。表中的预期不能直接当作已执行或已通过的结果。

落地前尚需对齐的能力点：复杂路段暂停解除机制，以及醒来恢复不覆盖用户之后修改的设置。本稿没有通过新增事件解决这些差异，也没有修改现有前端、BFF 或 Dify。
